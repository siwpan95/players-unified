# 命令行接口（CLI）参考

`tools/pp_cli.py` 把 `<仓库根>` 变成一个能在**命令提示符**里直接使唤的
工具。它自己不做播放、不做解码，只负责两件事：

1. **本地编排** —— 启动播放器、跑自检、构建、体检环境、装卸载命令；
2. **控制通道客户端** —— 跟已经跑起来的播放器说话（查询状态、定位、调用插件命令、订阅事件）。

```
                    ┌─────────────────────────────────────────┐
   cmd / PowerShell │  pluginplayer  (= pluginplayer.cmd 垫片)  │
   ────────────────▶│            tools\pp_cli.py              │
                    └───────┬──────────────────────┬──────────┘
                            │ 直接起进程             │ JSON-RPC over TCP
                            │ （stdio 继承，不捕获）  │ （127.0.0.1:7911，强制令牌）
                    ┌───────▼──────────┐   ┌───────▼──────────────────┐
                    │ dist\pluginplayer.exe │  dist\pluginplayer.exe --hidden --rpc-port 7911
                    │ build.py / ffmpeg     │  （同一个宿主，另一个实例也照样能控）
                    └──────────────────┘   └──────────────────────────┘
```

与播放器本身的分工：`.exe` 的 `--help` 讲的是**播放器自己的**选项；CLI 的 `--help`
讲的是**命令与子命令**。两者都有 `--help`，互不覆盖。

## 1. 安装：让 `pluginplayer` 在任意目录可用

```bat
:: 只装（不写任何环境变量）
/Python314/python.exe tools\pp_cli.py install-cli

:: 先看看会装到哪、会不会落在 PATH 上
/Python314/python.exe tools\pp_cli.py install-cli --dry-run
```

`install-cli` 写 **两份** 垫片：

| 位置 | 内容 | 用途 |
|---|---|---|
| 仓库根 `pluginplayer.cmd` + `pp.cmd` | `PP_ROOT=%~dp0` | clone 下来就能用；仓库整体搬走也不失效 |
| PATH 目录 `pluginplayer.cmd` + `pp.cmd` | `PP_ROOT=<绝对路径>` | 在任意目录直接敲 `pluginplayer` |

**目标目录怎么挑**（按顺序取第一个"已在本机 PATH 上且可写"的）：

1. `--shim-dir 目录`（显式指定，优先级最高）
2. 环境变量 `PP_BIN_DIR`
3. `<Python 前缀>\Scripts` —— Python 自己的用户级脚本目录，本机 `/Python314\Scripts`
   本来就在 PATH 上，**所以默认情况不需要改任何环境变量**
4. `%LOCALAPPDATA%\PluginPlayer\bin`

如果挑到的目录不在 PATH 上，CLI 会**照原样打印三条可行修法**（改用户级 PATH 的
PowerShell 一行命令 / `--add-to-path` / 换目录），而不是自己悄悄改环境变量。
`--add-to-path` 才会动手，且只写 `HKCU\Environment\PATH`（用户级），用 `winreg`
读取-追加-写回，绕开 `setx` 的 1024 字符截断与"把系统 PATH 混进用户 PATH"的老坑。

卸载：

```bat
/Python314/python.exe tools\pp_cli.py uninstall-cli
```

只删**带本工具标记**（文件里有 `PP_CLI_SHIM` 字样）的垫片；你自己手工放的同名文件
会被跳过并打印出来。仓库根那两份是仓库的一部分，不参与卸载。

### 垫片为什么长这样

```bat
@echo off
rem PP_CLI_SHIM v1 - generated by tools/pp_cli.py install-cli; safe to delete.
setlocal
set "PP_ROOT=<仓库根>\"
set "PP_PY=/Python314/python.exe"
...
if defined PP_PYTHON set "PP_PY=%PP_PYTHON%"     :: 1) 环境变量优先
if defined PP_PY if not exist "%PP_PY%" set "PP_PY="
if exist "<安装时的解释器路径>" set "PP_PY=..."   :: 2) 安装时记下的绝对路径
where py     >nul 2>nul  ->  PP_PY=py, PP_PYARG=-3   :: 3) py launcher
where python >nul 2>nul  ->  PP_PY=python            :: 4) PATH 上的 python
:pp_run
"%PP_PY%" %PP_PYARG% "%PP_ROOT%tools\pp_cli.py" %*
```

三条硬约束（都有回归测试钉着，见 `tests/cli_check.py`）：

- **纯 ASCII + CRLF**。cmd.exe 按当前代码页（本机 GBK）解读 `.bat`，文件里混入中文
  在别的机器上会乱码/截断。这份约定与 `build.py:make_launcher()` 生成
  `run.bat`/`selftest.bat` 时遵守的是同一条。
- **解释器路径一律加引号**，否则 `C:\Program Files\...` 这种路径会在空格处被拆词。
  代价是 `py -3` 这种"命令 + 参数"形式不能整体加引号，所以拆成 `PP_PY` + `PP_PYARG`。
- **`PP_ROOT` 统一带尾部分隔符**，脚本里固定写 `"%PP_ROOT%tools\pp_cli.py"`，
  这样绝对路径版和 `%~dp0` 版能共用同一份脚本体（测试会断言两份脚本除 root 赋值行
  外完全一致，避免将来各自漂移）。

## 2. 命令总览

```bat
pluginplayer --help
```

### 本地编排

| 命令 | 作用 |
|---|---|
| `open <媒体> [选项]` | 启动播放器播放媒体（**默认命令**：`pluginplayer 影片.mp4` 等价） |
| `selftest [媒体] [选项]` | 无人值守自检，产出 JSON 报告；**不给媒体时自动生成样例** |
| `plugins [--remote]` | 列出插件（默认离线读 `dist/plugins`；`--remote` 问运行中的实例） |
| `manifest` | 重新生成 `plugins/manifest.sha256` |
| `build [参数...]` | 转发给 `build.py`（`--release` / `--smoke` / `--apitest` / `--clean` / `--debug` …） |
| `host-js [选项]` | 启动进程外 JS 插件宿主（Node + Cordis） |
| `doctor` | 环境与依赖体检（**真校验**：存在性 + 哈希 + 版本 + 端口） |
| `install-cli` / `uninstall-cli` | 装 / 卸 `pluginplayer` 命令 |
| `version` | 版本与环境摘要 |

### 控制通道（需要播放器以 `--rpc-port N` 启动）

| 命令 | 作用 |
|---|---|
| `status` | 一次拿 `player.info` + `player.stats` + 当前音量 |
| `play` / `pause` / `toggle` / `stop` | 播放控制 |
| `seek <秒\|+N\|-N>` | 定位（带 `+`/`-` 为相对当前位置） |
| `volume [0..1\|+N\|-N]` | 音量；不给参数则查询 |
| `mute [on\|off\|toggle]` | 静音（默认 toggle） |
| `speed [倍率]` | 变速；不给参数则查询 |
| `cmd <命令名> [参数...]` | 调用插件命令（`command.invoke`） |
| `commands` / `services` | 列出插件命令 / 服务 |
| `events [选项]` | 订阅并流式打印内核事件 |
| `rpc <方法> [选项]` | 原始 JSON-RPC 调用（逃生舱） |
| `quit` | 让远端播放器退出 |

## 3. 全局选项

两种写法等价 —— 放在命令前或命令后都行：

```bat
pluginplayer --json status
pluginplayer status --json
```

| 选项 | 默认 | 说明 |
|---|---|---|
| `--port`, `-p` N | 7911 | 控制通道端口 |
| `--token` HEX | — | 直接给令牌 |
| `--token-file` 路径 | `dist/config/rpc-token.txt` | 令牌文件 |
| `--timeout` 秒 | 10 | 单次请求超时 |
| `--json` | 关 | 输出机器可读 JSON |
| `-q`, `--quiet` | 关 | 少说话 |
| `-v`, `--verbose` | 关 | 打印调试信息 |

**令牌解析顺序**（与 `tools/rpc_client.py` 完全一致，便于互相对照排查）：

1. `--token HEX`
2. 环境变量 `PP_RPC_TOKEN`
3. `--token-file` 指定的文件
4. `dist/config/rpc-token.txt`

令牌由播放器**每次启动重新生成**。所以"昨天还好好的，今天认证失败"是正常现象 ——
重读令牌文件即可。这也是把认证失败单独做成退出码 4 的原因：它的修法与"连不上"（3）
完全不同。

## 4. 命令详解

### 4.1 本地编排

```bat
:: 播放（前台运行，直到播放器退出；退出码透传）
pluginplayer open a.mp4 --hidden --port 7911 --volume 0.8

:: 拖给播放器的其它选项也能给：--size / --start / --no-audio / --log-level / --write-dir
pluginplayer open a.mkv --size 1920x1080 --start 120
pluginplayer open a.mkv --write-dir <截图目录A> --write-dir <截图目录B>

:: 不想开控制通道（最省心的加固方式）
pluginplayer open a.mkv --no-rpc

:: `--` 之后原样透传给 pluginplayer.exe，CLI 不再解析
pluginplayer open a.mkv -- --reload 2
```

`open` 用**全局的 `--port`**，CLI 自己把它翻译成播放器的 `--rpc-port`。
如果你误写了 `--rpc-port`，CLI 会明确告诉你该写 `--port`（而不是笼统报"未知选项"）。

```bat
:: 自检：不给媒体就自己找/生成样例（8 秒 1280x720），零参数可用
pluginplayer selftest
pluginplayer selftest --frames 90 --out selftest_out_cli
```

实测 11/11 项通过（见第 8 节）。`selftest` 的"零参数可用"是刻意做的：
样例缺失时用 `vendor/ffmpeg` 现场生成（命令与 `selftest.bat` 完全一致），
所以不必先手工准备素材。

```bat
:: 插件
pluginplayer plugins                 :: 离线：起 exe 跑 --list-plugins，不开控制通道
pluginplayer plugins --remote        :: 在线：向运行中的实例要 plugin.list

:: 体检
pluginplayer doctor
pluginplayer --json doctor           :: 机器可读，脚本里用 ok 字段判断
```

`doctor` 的 16 项检查**都是真跑的**，不是看文件名猜：

| 检查 | 怎么验的 |
|---|---|
| Python / 编译器 g++ / Node.js | 真起进程取 `--version` 首行 |
| 内核 exe / 运行时 DLL / 插件目录 | 逐个文件存在性 + 大小 |
| **插件完整性清单** | 对 `dist/plugins/*.dll` **逐个重算 SHA-256** 与 `manifest.sha256` 比对，并查出"未登记"与"清单有但文件没了"两种偏差 |
| vendor 依赖 / ffmpeg.exe | 头文件、导入库、可执行文件的存在性 |
| 控制通道 | 真去 `connect` 一次 |
| CLI 命令 | `shutil.which("pluginplayer")` |

`FAIL` → 退出码 6；`WARN` 不影响退出码（例如"播放器没在跑"只是告警）。

```bat
:: 构建（不做二次实现，原样转发）
pluginplayer build --release
pluginplayer build --smoke
pluginplayer build --plugins osd_stats,snapshot
```

### 4.2 控制通道

典型的"无人值守控制"套路：

```bat
:: 1) 后台开一个隐藏窗口的播放器，授权控制通道
start "" dist\pluginplayer.exe --hidden --rpc-port 7911 a.mp4

:: 2) 另开一个窗口控制它
pluginplayer status
pluginplayer seek +30
pluginplayer volume 0.5
pluginplayer cmd effect.set gray
pluginplayer cmd snapshot <截图目录>
pluginplayer events --topic player.completed --seconds 600
pluginplayer quit
```

`status` 的人类可读输出（实测）：

```
媒体   : test_assets/sample.mp4
容器   : mov,mp4,m4a,3gp,3g2,mj2  视频 h264 1280x720 30.00fps  音频 aac 48000Hz/1ch
进度   : 0:08.00 / 0:08.00  (100.0%)
状态   : 播放   倍速 1.00x   音量 0.800
时钟   : 主 8.000  视频 7.967  音频 8.000
统计   : 解码 428  显示 408  丢帧 20  实测 2.02 fps  vqueue 0  abuf 0
状态   : 已到文件末尾 (eof)
```

`--json` 输出 `{ok, info, stats, volume}` 四个键。音量是额外查的：
`player.volume` 传 `value=-999` 是"只查不改"（`control.cpp` 里 `v <= -998` 直接回值）；
`player.mute` **没有**纯查询路径（不给 `value` 就是 toggle），所以状态里只报音量。

事件流：

```bat
pluginplayer events                          :: 订阅全部，10 秒
pluginplayer events --topic app.tick --count 5
pluginplayer events --seconds 600 --raw      :: JSONL，便于喂给别的工具
```

逃生舱 —— 任何控制通道方法都能直接调：

```bat
pluginplayer rpc ping
pluginplayer rpc player.seek --p seconds=12.5
pluginplayer rpc command.invoke --params "{\"name\":\"stats\"}"
pluginplayer rpc topic.subscribe --p topic=app.tick
```

`--p k=v` 的 `v` 能解析成 JSON 字面量就当字面量（`--p seconds=12.5` 送数字，
`--p name=gray` 送字符串），因此不用手写转义。

## 5. 退出码

| 码 | 含义 | 怎么办 |
|---|---|---|
| 0 | 成功 | — |
| 1 | 一般失败（远端超时、插件命令返回非零等） | 看 [ERR] 正文 |
| 2 | **用法错误**（未知命令/选项、参数非法、缺参数） | `--help`；参数错误**不启动任何进程** |
| 3 | 控制通道连不上 | 确认播放器在跑且带 `--rpc-port N` |
| 4 | 控制通道认证失败 | 重读 `dist/config/rpc-token.txt`（令牌每次都换） |
| 5 | 远端返回错误（应答 `ok:false`） | 看错误正文（如"命令不存在"） |
| 6 | 环境或依赖缺失（编译器/vendor/dist 未构建） | 跑 `doctor` |
| 130 | 被 Ctrl-C 中断 | — |

转发类命令（`open` / `selftest` / `build` / `plugins` / `manifest` / `host-js`）
**原样返回子进程的退出码**，不会把它压成 1。所以
`pluginplayer selftest` 的退出码就是自检结果，`pluginplayer build --release` 的
退出码就是 `build.py` 的退出码，脚本里可以直接 `if errorlevel 1 ...`。

## 6. 设计原则

CLI 的命令语法参考了 `deepseek-harness-master/apps/cli`（`dsh` 启动器）的几条做法：

| 原则 | 本项目怎么落地 |
|---|---|
| **语法归属清晰**：启动器只解析自己认识的 flag，其余原样交给被启动的东西 | `--` 之后的一切原样透传给 `pluginplayer.exe`；第一个不认识的 token 立即报错（exit 2），不"猜" |
| **模式分离** | 本地编排（把子进程 stdio 直接继承）与控制通道（走 JSON-RPC）是两组命令，互不干扰 |
| **机器可读** | 每个命令都支持 `--json`，脚本可解析；`doctor --json` 还带 `ok` 字段与退出码一致 |
| **失败要说清楚** | 分级退出码（见上）+ 错误信息带"怎么修"（例如 3 号错误会打印该用什么命令启动） |

另外两条是本项目自己的口径：

- **不做二次实现**：`build` / `selftest` 只转发，逻辑仍在 `build.py` 与 `pluginplayer.exe`，
  避免"同一个行为两处实现、然后走偏"。
- **参数先校验再启动**：`--size` / `--volume` / `--start` / `--log-level` / `--frames`
  / `--port` 的边界与 `src/core/main.cpp` 一一对齐，非法值在**起进程之前**就退 2。
  这样 `pluginplayer open --size 99999x99999 a.mp4` 不会先弹出窗口再报错。

### 输出编码

CLI 按输出目标分流（`setup_stdio()`）：

- **输出到终端**（`isatty()`）→ 保持控制台代码页（本机 GBK），只加 `errors="replace"` 兜底。
  强行把 TTY 上的 stdout 改成 UTF-8 会让 cmd.exe 里的中文直接乱码。
- **输出到文件/管道** → 用 UTF-8，这样 `pluginplayer status --json > s.json` 落盘可读。

表格对齐用 `disp_width()` 按"中日韩全角占 2 列"计算，不是 `len()`。

## 7. 已知边界

- **`open` 是前台阻塞的**。它就是"把播放器跑起来"，退出码 = 播放器退出码。
  要做无人值守控制请配 `--hidden` 并在另一个窗口发命令。
- **`volume +N/-N` 是两次往返**（先读 stats 再写），不是原子的。并发改音量时可能丢一次更新。
- **`mute` 没有纯查询**。协议里不给 `value` 就是 toggle，想"看一眼是否静音"只能
  `pluginplayer rpc player.mute` —— 但那会切换状态。所以 `status` 里不显示静音。
- **`events` 需要自己带时长**（`--seconds`，默认 10）。控制通道的 1 秒空闲超时只用来
  周期性唤醒 `recv`，服务端不会主动断开，所以不加时限就会一直等下去。
- **`cmd` 的全局选项在命令名之后会被当作参数**。`pluginplayer cmd stats --json` 里的
  `--json` 是**插件命令的参数**；要 CLI 的 JSON 输出请写 `pluginplayer --json cmd stats`，
  或用 `--`：`pluginplayer cmd stats -- --json`。
- **`--add-to-path` 只写用户级 PATH**，且**当前窗口不会立刻生效**（Windows 需要新终端）。
- **`rpc` 是逃生舱**：它不校验方法名与参数，远端报什么就转什么。日常用的命令都有专门
  子命令（带参数校验与更好的人类可读输出）。
- **CLI 不随 `dist/` 发布**。`dist/` 保持"17 个文件 / 127 MB"的干净载荷（`build.py --release`
  的口径），CLI 属于仓库侧的运维工具，装在 PATH 目录里。
- **`host-js` 只负责起进程**。`host-js/node_modules` 缺失时只给告警（需要 `npm install`），
  不代跑 `npm`。

### 经 cmd 垫片从别的目录调用（实测）

在 `C:\Windows` 下用 `cmd /c` 调用 PATH 上的垫片与仓库根垫片：

```
pluginplayer.cmd --version    rc=0   pluginplayer-cli 1.0.0
pluginplayer.cmd status       rc=0   媒体   : test_assets/sample.mp4
```

## 9. 排查

| 现象 | 原因 | 修法 |
|---|---|---|
| `[ERR] 找不到控制通道令牌文件` | 播放器没启动过，或从没用过控制通道 | `pluginplayer open <媒体>`（默认就开 7911） |
| `[ERR] 连不上控制通道 127.0.0.1:7911` | 没在跑 / `--rpc-port 0` / 端口不符 | `--port N` 对齐；或先 `open` |
| `[ERR] 控制通道认证失败` | 令牌过期（每次启动都换） | 删掉 `PP_RPC_TOKEN` 环境变量，重读令牌文件 |
| `[ERR] 未知命令: xxx` + `你是指: ...` | 打错了 | 按建议改，或 `--help` |
| `[ERR] 非法的 --size 值` | 越界（合法 160..8192） | 改数值；注意这条**不会**启动播放器 |
| `[ERR] 命令不存在: xxx` | 插件命令名错 | `pluginplayer commands` 看全量 |
| `[WARN] PATH 中找不到 pluginplayer` | 没装或装的目录不在 PATH | `pluginplayer install-cli`，或按提示的三条修法之一 |
| 输出里中文变成 `?` 或乱码 | 控制台代码页与字节不符 | 终端里跑（CLI 会保持代码页）；重定向到文件时是 UTF-8，用 UTF-8 查看 |

一次性自查：

```bat
pluginplayer doctor
pluginplayer --json doctor > doctor.json
```
